# 03 步态参数化与优化

## 3.1 关节轨迹（`gait.py`）

每个执行器 i 的目标角：

```
q_i(t) = offset_i + ramp(t) · Σ_{h=1..H} A_{i,h} · sin(h · θ(t) + φ_{i,h}),     H = 2
```

- **占空比相位变形** θ(t)：设一个周期内进度 c = (f·t) mod 1，发力冲程占比为 duty：
  ```
  θ = π · c / duty                               c < duty      （前半个正弦 = 发力冲程）
  θ = π + π · (c − duty) / (1 − duty)            c ≥ duty      （后半个 = 回程）
  ```
  这让发力冲程可以比回程快（或慢），而周期长度不变。
- `ramp(t)` 在前 1.5 s 从 0 线性升到 1，避免 t = 0 时猛然起步；这一段**仿真但不计分**。
- **二次谐波**在相位平移 π 下不变，正好能表达脚蹼的"顺桨"（发力时张开、回程时收拢）。
  它**不是产生净推力的必要条件**：单谐波、纯正弦（占空比固定 50%）仍有 0.156 m/s，
  单谐波 + 自由占空比有 0.296 m/s（这两个数是在舵机模型之前测的，只说明"非必要"这一定性结论）。
- 分组：同类关节（所有腿的髋、所有腿的膝、所有腿的脚蹼）共享幅度与中心角，降低维度。

### 搜索范围（`config.json` 的 `gait`）

| 参数 | 范围 |
|---|---|
| 频率 f | 0.2–2.5 Hz |
| 占空比 duty | 0.25–0.75 |
| 幅度 A | 0–0.9 rad（二次谐波同范围） |
| 中心角 offset | ±0.5 rad |
| 相位 φ | 0–2π |

所有参数归一化到 [0, 1] 后交给优化器。

### 维度

```
自由相位（family = null）: 1 (f) + 1 (duty) + H × (3 幅度组 + 12 个独立相位) + 3 中心角组 = 35
步态族（family 固定）   : 1 + 1 + H × (3 幅度组 + 3 个关节类型相位) + 3 = 17
```

## 3.2 步态族

设定 `gait.family` 后，各腿的时序固定为教科书步态，只搜"每类关节一个相位"（所有腿共享）：

| 步态族（代码名） | 常用名 | 各腿相对左前腿 FL 的延迟（周期的比例） |
|---|---|---|
| `diag` | trot，对角步态 | FR 0.5，BL 0.5，BR 0 （FL+BR 一组，FR+BL 一组） |
| `lr` | pace，同侧步态 | FR 0.5，BL 0，BR 0.5 （左侧一组，右侧一组） |
| `fb` | bound，前后跳跃 | FR 0，BL 0.5，BR 0.5 （前腿一组，后腿一组） |
| `wave` | walk，波形（侧序） | BR 0.25，FR 0.5，BL 0.75 |
| `inphase` | pronk，四腿同步 | 全部 0 |

- 延迟作用在**时间**上、在占空比变形之前：trot 里右腿做的正是左腿半个周期前做的动作，即使发力冲程比回程短也一样。
- 腿和关节类型**从模型几何自动识别**：一条腿 = 浮动机身下某个子刚体以下的链；按安装点位置分前/后、左/右；
  关节类型 = 它在链上的深度。（旧版按执行器名字识别，名字不是 FL/FR/BL/BR 的机器人会静默地退化成"四腿同步"。）

### 判断一个步态属于哪一族（`SineGait.structure`）

取一次谐波幅度最大的关节类型，读出每条腿相对 FL 的相位延迟（周期比例），
与每个步态族的参考延迟比较，取 FR、BL、BR 三条腿**平均圆周距离**最小的族为"最近步态族"，
该距离即"偏离度"（0 = 完全一致，0.5 = 完全相反）。

## 3.3 目标函数与约束（`simulate.py` 的 `score`）

测量量：
- **速度** = 计分窗口内机身位移在**初始朝向**上的投影 / 窗口时长（转圈会被自动惩罚）。
- **体长/秒** = 速度 / 0.239 m。
- **航向、横滚、俯仰 RMS**：航向相对起始朝向的偏差；横滚、俯仰为机身姿态角。

两种目标（`objective.mode`）：

```
speed:  objective = 体长/秒 − w_energy · 平均功率            (w_energy 默认 0)
power:  objective = − 平均功率，       要求 速度 ≥ min_speed
```

**约束是限值，不是权重**（默认 航向 10°、横滚 10°、俯仰 15° RMS；可选出水比例上限）：

```
penalty = Σ_k max(0, RMS_k − limit_k) / limit_k
        (+ max(0, surfacing − s_lim) / s_lim)          若设置了出水上限
        (+ max(0, min_speed − speed) / min_speed)       power 目标
fitness = objective                 若 penalty = 0     （可行）
        = −1000 − penalty           否则              （不可行带，按超限程度排序）
        = −1e6                      仿真发散（速度 > 5 m/s 或 NaN）
```

**可行性优先**：任何超限步态的得分都低于所有可行步态，速度不能"买回"违约。

为什么这样设计（论文可写的点）：
- 旧版用加法权重 `速度 − w_yaw·偏航率 − w_attitude·...`。权重只在调参时的速度量级下有效；
  模型修好、腿真正能动起来后，速度项压倒惩罚，最优步态横滚 42°、偏航 44°。
- 旧版"每超 100% 扣 1 体长/秒"隐含假设没有步态超过 1 体长/秒；无约束步态可达 5 体长/秒。
- fitness 数值在不同设置之间不可比，论文只报告物理量。

## 3.4 测量方法

- **三阶段**：静置 settle 1.0 s（让机器人浮稳，结果缓存复用）→ 渐入 1.5 s（不计分）→ 计分窗口 8 s。
- **整数周期窗口**：计分窗口向上取整到整数个划水周期。速度按端点位移计算，停在半个周期中间会有偏差，慢步态尤其明显。
- **唯一仿真循环**：可视化、步态图、GIF 都通过 `rollout()` 的回调取数据，所见即所评分。

## 3.5 优化器

- **CMA-ES**（Hansen & Ostermeier 2001），`cma` 包。无梯度进化策略，因为标准 MuJoCo 不可微。
  （工作流参照 Lee 等 2025，他们用可微仿真 + 梯度法。）
- 种群 16，初始步长 σ0 = 0.25（归一化空间），通常预算 2500 次评估；种子必须非零（cma 把 0 当作"用时钟"）。
- 并行：spawn 进程池，每个候选一个进程；并行与串行逐位一致。
- **收敛判据**：fitness 曲线走平**且** σ 缩小。
- **已知问题**：35 维自由相位空间强多峰，2500–4000 次评估后自由搜索仍明显差于步态族搜索
  （自由搜索的最优解与某步态族相似，但速度只有该族最优解的 1/3–1/6）。
  因此研究默认用 17 维步态族搜索，自由搜索用来观察"不预设时会自发靠近哪种步态"。
- 单次运行只是模型允许值的下界；比较条件必须用多个种子。
