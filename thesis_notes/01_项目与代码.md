# 01 项目与代码

## 1.1 要解决的问题

四足划水机器人（参照河狸类仿生机器人）在水面/水下靠腿和脚蹼划水前进。已有文献通常**人工挑两三种步态**
（对角、前后、波形）做对比。但真实的步态空间大得多：划水频率、每个关节的幅度、各关节相位差、
关节中心角、谐波成分、发力/回程时间比（占空比）互相耦合。

swimopt 的做法：**把机器人模型当作可替换的输入**，在仿真里给每个关节一条参数化轨迹，
用无梯度优化器 CMA-ES 在整个参数空间里搜索"满足约束的最快（或最省功率）"的步态，
而不是只在三个点上采样。

它属于**轨迹优化**（优化一个固定形式的周期轨迹的参数），**不是强化学习**（不学状态反馈策略）。

## 1.2 一次评估（rollout）做了什么

```
参数向量 x (35 维或 17 维, 归一化到 [0,1])
   │  gait.decode(x)
   ▼
每个关节的目标角 q_i(t) = 傅里叶级数 (含占空比变形)      ← 03 文件
   │  位置伺服 + 舵机力矩-转速模型                      ← 02 文件
   ▼
MuJoCo 刚体动力学 (dt = 2 ms, implicitfast 积分)
   │  每步: hydro.apply() 对每个几何体施加浮力/阻力/粘性/(升力)  ← 02 文件
   ▼
三个阶段: 静置 settle 1.0 s → 渐入 ramp 1.5 s (仿真但不计分) → 计分窗口 8 s (取整到整数个划水周期)
   │
   ▼
测量: 沿初始朝向的前进距离 → 速度; 机械功率; 航向/横滚/俯仰 RMS;
      升力/阻力各自的前向冲量; 关节峰值转速; 舵机饱和比例; 肢体出水比例
   │  score()
   ▼
fitness (先可行性、后目标)                                ← 03 文件
```

CMA-ES 每代 16 个候选，并行评估（每个候选一个进程），通常 2500 次评估一轮，16 核笔记本上约 4–5 分钟。

## 1.3 四层解耦架构

| 层 | 文件 | 职责 | 换机器人时要改吗 |
|---|---|---|---|
| ① 模型层 | `robots/*.xml` | 机器人几何、质量、关节、执行器 | **只改这里** |
| ② 物理层 | `hydro.py` | 与机器人无关的 Morison 型水动力（向量化） | 不改（系数在 config 里按名字匹配） |
| ③ 控制层 | `gait.py` | 与机器人无关的傅里叶 + 占空比步态；腿和关节类型从几何自动识别 | 不改 |
| ④ 优化层 | `optimize.py` | CMA-ES、并行评估、日志 | 不改 |
| 粘合 | `simulate.py` | `Swimmer` 类：唯一的仿真循环 `rollout()`、评分 `score()`、舵机模型 | 不改 |

所有参数集中在 `config.json`（允许 `//` 注释）。
